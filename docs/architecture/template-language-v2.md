# Архітектура Template Language v2

## Причина зміни

v1 поєднував англійські шляхи, скорочені глобальні назви й окремі правила для однієї та кількох осіб. Це створювало розбіжності між Довідником, валідатором і Rust-генератором. v2 має одну українську схему, нумерацію від 1 і однакові правила в усьому застосунку.

## Схема і реєстр

Єдине джерело правди — `src/shared/template-language/registry.v2.json`. Воно містить поля військовослужбовця, ролі й поля підписантів, поля документа, типи, приклади, доступність відмінків та модифікатори. TypeScript імпортує JSON для Довідника, конструктора і клієнтської перевірки. Rust вбудовує той самий JSON через `include_str!` для валідації та генерації. Окремих списків дозволених змінних немає.

Токен має вигляд `{{назва:модифікатор:модифікатор}}`. Військовослужбовець — `військовий_{номер}_{поле}`, підписант — `{роль}_{поле}`, дата — `дата_рапорту`.

## Несумісність і міграція

Сумісності з v1 немає навмисно. Валідатор відхиляє старі ключі. Власник шаблону відкриває DOCX, замінює старі токени відповідниками з Довідника та запускає повну перевірку. Стартові шаблони постачаються лише у v2.

Схема БД має версію 2. Міграція додає `personnel.gender` зі значеннями `чоловіча`, `жіноча` або порожнім значенням. Збережена стать має пріоритет; за її відсутності допускається визначення за по батькові з явною помилкою, якщо визначення неможливе.

## Морфологія і розширення

Pipeline застосовує довільну кількість сумісних модифікаторів зліва направо. Реєстр контролює сумісність за типом. Звання мають контрольовані форми, посади — словник термінів та загальні правила. Нові ручні винятки додаються у морфологічний сервіс без зміни синтаксису шаблонів.

## Стратегія тестування

TypeScript-тести перевіряють реєстр, парсер, усі відмінки, стать, складні імена, регістр і попередній перегляд. Rust-тести перевіряють той самий реєстр, помилки, конфлікти, послідовний pipeline, морфологію, розбиті Word-токени й DOCX. Інтеграційний сценарій: створення/міграція БД → перевірка контрольного DOCX → генерація → повторна перевірка архіву та відсутності незамінених токенів.
