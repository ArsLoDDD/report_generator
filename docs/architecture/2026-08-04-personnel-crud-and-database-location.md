# Особовий склад: CRUD і розташування бази даних

Дата рішення: 04.08.2026.

## Причина

Особовий склад має бути єдиним джерелом даних для генерації рапортів. Поточний екран лише відображає скорочений набір полів і не дозволяє створювати, оновлювати або видаляти записи. Окрема папка «База даних» також більше не відповідає погодженій структурі файлів програми.

## Рішення

- SQLite-файл `особовий_склад.db` зберігається безпосередньо в корені робочої папки програми, поруч із Windows EXE.
- Під час першого запуску після оновлення наявний файл із `База даних/особовий_склад.db` переноситься в корінь без втрати даних.
- Нові бази створюються порожніми. Демонстраційні записи не додаються до робочої БД; тестові дані існують лише всередині автоматичних тестів.
- Відсутній файл БД не створюється під час запуску. До першого додавання особи застосунок використовує порожню SQLite-схему в пам’яті; файл у корені створюється перед першим записом.
- React отримує особовий склад тільки через типізований `personnelService`; компоненти не викликають Tauri-команди напряму.
- Rust реалізує повний контракт `list/create/update/delete` і повторно перевіряє дані перед записом у SQLite.
- Один компонент форми використовується і для додавання, і для редагування всіх полів особи.
- Таблиця показує всі затверджені поля БД, має горизонтальне прокручування та закріплений заголовок.
- Початковий порядок таблиці завжди відповідає `id ASC`; неповні записи позначаються попереджувальним оформленням.
- Видалення потребує явного підтвердження.

## Системні попередження

Під час запуску backend фіксує важливі стани: база була відсутня, папка шаблонів не містила DOCX-файлів, у базі немає військовослужбовців. Frontend відображає ці повідомлення в нижній частині бічної панелі. Це інформаційні попередження; автоматично створені службові файли не маскують факт їх початкової відсутності.

## Задіяні модулі

- `features/personnel` — таблиця, форма, локальний UI-стан і CRUD-координація;
- `shared/services/personnelService` — типізований Tauri-контракт;
- `src-tauri/personnel.rs` — перевірка та SQL-операції;
- `src-tauri/main.rs` — шлях БД, міграція і діагностика запуску;
- `app/sidebar` (поточна композиція в `App.tsx`) — системні попередження;
- `features/templates` — компонування без окремого заголовка сторінки.

## Вплив і міграція

- Існуючі записи зберігаються: старий файл переноситься лише якщо нового файла в корені ще немає.
- Якщо обидва файли існують, чинним джерелом є кореневий файл; старий не перезаписує його.
- Мова шаблонів і структура таблиці `personnel` не змінюються.
- Після CRUD-операцій список у React оновлюється, тому генератор рапортів одразу бачить актуальні дані.

## Необхідні тести

- створення, читання, оновлення і видалення запису SQLite;
- відхилення невалідного ІПН та дубліката;
- створення порожньої БД без демонстраційних записів;
- міграція старого файла БД у корінь;
- робота форми додавання/редагування і підтвердження видалення;
- відображення всіх колонок і системних попереджень;
- сторінка шаблонів без окремого заголовка.
