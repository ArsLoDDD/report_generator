# Офлайн-оновлення просунутої версії

## Що отримує користувач

Починаючи з версії `0.2.0`, робочі дані зберігаються не біля виконуваного файла, а в системній локальній папці застосунку. Під час першого запуску програма без видалення оригіналів переносить туди наявну БД, налаштування, кастомні поля, шаблони, готові рапорти та резервні копії. Інсталятор автоматично створює актуальний ярлик програми на робочому столі; файлові оновлення також відновлюють цей ярлик.

Користувач відкриває **Налаштування → Оновити застосунок**, обирає один файл `.shupd`, перевіряє версію й опис та натискає **Створити копію та оновити**. Програма:

1. перевіряє редакцію, архітектуру, версію та SHA-256;
2. створює повний ZIP-архів SQLite-бази, налаштувань, кастомних полів, шаблонів і готових рапортів;
3. перевіряє цифровий підпис інсталятора;
4. закривається, оновлюється й запускається знову;
5. при першому запуску виконує всі міграції старої БД.

Стара або пошкоджена збірка, пакет іншої редакції чи файл без правильного підпису не встановлюються.

## Одноразове встановлення версії 0.2.0

Версії до `0.2.0` ще не мають вбудованого апдейтера. Їм один раз потрібно передати звичайний новий інсталятор `.exe`. Якщо стара програма працювала як переносна папка, інсталятор потрібно покласти в цю папку поруч із БД, налаштуваннями й каталогом `Шаблони`, закрити стару програму та запустити інсталятор. Якщо стара версія вже встановлена, достатньо запустити інсталятор поверх неї. В обох випадках дані копіюються автоматично, а наступні версії можна роздавати одним файлом `.shupd`.

## Як сформувати файл оновлення локально

Збірка пакета виконується на Windows:

```powershell
npm run update:build -- --version 0.3.0 --notes "Короткий опис змін"
```

Перед складанням команда синхронізує версію, запускає повну перевірку, збирає просунуту NSIS-версію, підписує її та створює:

```text
release/Shablonizator-Advanced-0.3.0.shupd
```

Саме цей файл передається користувачам. Для локальної збірки приватний ключ очікується у `.tauri-private/shablonizator-updater.key` або у змінній `TAURI_SIGNING_PRIVATE_KEY`.

## Як сформувати файл у GitHub Actions

У secrets репозиторію потрібно один раз додати:

- `TAURI_SIGNING_PRIVATE_KEY` — повний вміст приватного ключа;
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль ключа, якщо він заданий.

Після цього кожен push автоматично збирає просунуту версію й кладе в один артефакт **Shablonizator-Advanced-Windows** два файли: звичайний інсталятор `.exe` та оновлення `.shupd`. Версія береться з `package.json`, опис — з повідомлення останнього коміту.

Workflow також можна запустити вручну й указати потрібну версію та опис. Pull request лише перевіряє складання просунутої версії без підписаного файла, тому секретний ключ не передається до коду з PR. Проста й адмінська редакції цим workflow не збираються.

## Ключ підпису

Локальний приватний ключ навмисно ігнорується Git та не потрапляє до застосунку. Його необхідно зберегти щонайменше у двох захищених місцях. Якщо ключ буде втрачено, вже встановлені програми не зможуть приймати нові оновлення; заміна публічного ключа потребуватиме нового звичайного інсталятора `.exe`.

Публічний ключ зберігається в `src-tauri/updater.pubkey` і в конфігурації просунутої збірки. Міняти його у звичайному оновленні не можна.
