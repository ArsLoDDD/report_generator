# RaportGen — рішення, які треба погодити перед реалізацією

Цей файл фіксує дизайн-рішення з інтерактивного макета. Після погодження він стає коротким контрактом для реалізації.

## Запропоновано

- Візуальний напрям: темний obsidian + приглушений olive, мінімум градієнтів.
- Щільність за замовчуванням: compact/balanced, рядок таблиці 40 px.
- Навігація: п’ять предметних груп, системні пункти внизу.
- Головна сторінка лишається «Генерація рапортів»; окремий вигаданий dashboard не додається.
- Попередження відкриваються першими лише коли вони є.
- Реєстри використовують таблицю + detail drawer.
- Екіпажі й позиції використовують картки + велике вікно сутності.
- БЧС і план польотів використовують окремий документний режим.
- Усі складні модалки мають fixed header/footer та scrollable body.
- Підтвердження й помилки показують точну причину та наслідок.
- Поточна яскраво-зелена primary action замінюється на оливкову; зелений залишається статусним.

## Відкриті рішення

- Чи залишати назву продукту «Шаблонізатор», чи перейти на «RaportGen» / службову назву.
- Чи потрібен глобальний пошук `⌘K` у першій версії редизайну.
- Чи дозволяти користувачу перемикати щільність інтерфейсу.
- Чи показувати повну назву підрозділу у sidebar, чи лише коротку.
- Чи зберігати вкладку «Історія» в картках до появи повного журналу подій.
- Чи робити світлий режим; макет виходить із dark-first вимоги.

## Не змінюється без окремого ТЗ

- структура й формати Excel-експорту;
- бізнес-логіка БЧС та плану польотів;
- локальна модель зберігання;
- правила імпорту старих Excel-баз;
- склад доменних сутностей.
