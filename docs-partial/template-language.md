# Мова шаблонів рапортів

## Призначення

Шаблон DOCX містить змінні у подвійних фігурних дужках. Під час генерації система замінює їх даними з SQLite та налаштувань програми.

```text
{{soldier.surname}}
```

Змінні чутливі до регістру. Пробіли всередині дужок не допускаються.

Вставляйте кожну змінну одним суцільним фрагментом тексту: наприклад, `{{soldier.fullName}}`. Не розділяйте її частини різним форматуванням у Word, бо DOCX може зберегти такий текст кількома окремими фрагментами.

## Військовослужбовці

Один запуск створює один рапорт. Якщо обрано одну особу, використовується об’єкт `soldier`, наприклад `{{soldier.fullName}}`. Якщо обрано двох або більше — використовується масив `soldiers` повної довжини: `{{soldiers[0].fullName}}`, `{{soldiers[1].fullName}}`, `{{soldiers[2].fullName}}` і так до останньої обраної особи. Генерація окремого рапорту для кожної особи наразі не підтримується.

| Поле в SQLite | Назва поля | Приклад значення | Змінна в шаблоні |
| --- | --- | --- | --- |
| `id` | Внутрішній ідентифікатор | `1` | Не використовується в шаблонах |
| `rank` | Звання | `Солдат` | `{{soldier.rank}}` |
| `surname` | Прізвище | `ВАСИЛЬОК` | `{{soldier.surname}}` |
| `given_name` | Ім'я | `Іван` | `{{soldier.givenName}}` |
| `patronymic` | По батькові | `Аркадійович` | `{{soldier.patronymic}}` |
| — (обчислюється) | Повне ПІБ | `ВАСИЛЬОК Іван Аркадійович` | `{{soldier.fullName}}` |
| `position` | Посада з військовою частиною | `Стрілець, військова частина А0000` | `{{soldier.position}}` |
| `tax_id` | ІПН, 10 цифр | `7462389812` | `{{soldier.taxId}}` |
| `birth_date` | Дата народження | `02.03.1999 року` | `{{soldier.birthDate}}` |
| `education_level` | Формат освіти | `вища` | `{{soldier.educationLevel}}` |
| `education_details` | Де здобуто освіту | `Львівська комерційна академія у 2002р` | `{{soldier.educationDetails}}` |
| `armed_forces_service_start_date` | З якого часу в ЗСУ | `у ЗС — із 27.02.2022 року` | `{{soldier.armedForcesServiceStartDate}}` |
| `position_assigned_date` | Дата призначення на посаду | `02.08.2026 року` | `{{soldier.positionAssignedDate}}` |
| `position_assignment_order` | Наказ про призначення | `КВ ОК «Пуп» №000-ПС` | `{{soldier.positionAssignmentOrder}}` |
| `military_id` | Військовий квиток | `АВ №077672` | `{{soldier.militaryId}}` |
| `assigned_vehicle_name` | Закріплений автомобіль | `Great Wall` | `{{soldier.assignedVehicleName}}` |
| `assigned_vehicle_registration` | Номер закріпленого автомобіля | `АВ 7265` | `{{soldier.assignedVehicleRegistration}}` |
| `created_at` | Коли створено запис | `2026-08-03 00:18:46` | Не використовується в шаблонах |
| `updated_at` | Коли оновлено запис | `2026-08-03 00:18:46` | Не використовується в шаблонах |

### Додаткові поля

Таблиця `personnel_custom_fields` зберігає затверджені додаткові поля без зміни базової структури: `personnel_id` (ідентифікатор військовослужбовця), `field_key` (стабільний ключ у `camelCase`) і `field_value` (значення). Після додавання нового ключа він стане доступним як `{{soldier.fieldKey}}` для однієї особи або `{{soldiers[0].fieldKey}}` для кількох — лише після оновлення Rust-словника та повної перевірки шаблону.

`[0]` — перша обрана особа, `[1]` — друга, `[2]` — третя і так далі до останньої обраної особи. Індексований синтаксис використовується лише у шаблоні для двох або більше обраних військовослужбовців.

## Як працює генерація

1. Користувач обирає DOCX-шаблон і одного або кількох військовослужбовців.
2. Програма перевіряє, що шаблон використовує `soldier.*` для однієї особи або `soldiers[index].*` для кількох.
3. Дані підставляються в один DOCX. Для кількох осіб всі вони доступні в єдиному масиві `soldiers`.
4. Створений файл записується у папку дня в `Згенеровані рапорти/ДД.ММ.РРРР/`. Для кожного нового рапорту окрема вкладена папка не створюється.

## Службові змінні

| Змінна | Дані |
| --- | --- |
| `{{mainRank}}` | Звання основного підписанта |
| `{{mainName}}` | ПІБ основного підписанта |
| `{{mainPosition}}` | Посада основного підписанта |
| `{{mainSignature}}` | Шлях до зображення підпису |
| `{{commanderName}}` | ПІБ командира |
| `{{chiefName}}` | ПІБ начальника штабу |

## Де зберігаються дані

| Дані | Єдине джерело істини | Роль SQLite |
| --- | --- | --- |
| Особовий склад | SQLite: `personnel`, `personnel_custom_fields` | Основне сховище |
| Шаблони DOCX | Вибрана папка шаблонів або файл, обраний користувачем | Не зберігаються в SQLite |
| Створені рапорти | Папка `Згенеровані рапорти/ДД.ММ.РРРР/` | Не зберігаються в SQLite |

Старі таблиці `templates` і `reports`, якщо вони лишилися у локальній тестовій БД від ранньої версії, не використовуються програмою. Вони не є джерелом даних і не видаляються автоматично, щоб не втратити дані без резервної копії.

## Майбутні затверджені поля

Нове поле додається до словника БД із стабільним ключем у `camelCase`. Воно стає доступним як `{{soldier.newFieldName}}` для однієї особи або `{{soldiers[0].newFieldName}}` для кількох лише після оновлення Rust-словника та повної перевірки шаблону.

## Перевірка

- Швидка перевірка перед генерацією перевіряє синтаксис і наявність даних для обраних осіб.
- Повна перевірка в «Шаблонах» також повертає попередження й інформацію про невідомі або застарілі змінні.
